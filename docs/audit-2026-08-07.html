2026-08-07 · Production readiness audit covering CSP/OCR, test suite, memory leaks, SEO, content accuracy, and code quality

CRITICAL — Must Fix Before Launch

critical OCR completely broken in production — CSP blocks tesseract.js workers

cspocr File: _headers

What: The CSP (_headers) blocks tesseract.js from creating blob workers and fetching from jsdelivr CDN. The feature works in astro dev but fails silently in production with a misleading "check your internet" error.

Impact: Flagship feature dead.

Fix: Self-host tesseract worker/wasm/traineddata in public/ocr/ (the kor.traineddata and eng.traineddata files already exist in the repo root — 7.4MB, unused). Then set workerPath/corePath/langPath in the TesseractWorker create options to point at /ocr/ instead of the CDN.

critical Poisoned worker promise — one OCR failure breaks all subsequent attempts

ocrstate File: OCR worker module

What: If createWorker fails once (network blip, CDN outage), _workerPromise caches the rejection forever. Every subsequent OCR attempt fails until full page reload.

Impact: OCR stays dead after one failure.

HIGH SEVERITY — Strongly Recommended

high 42 test failures across stimulant editors, item cards, stat breakdowns, chaos editors

tests File: tests/*.test.mjs

What: Test suite has 42 failing tests spanning stimulant editor logic, item card rendering, stat breakdown calculations, and chaos editor components. No tests pass reliably.

Impact: No confidence in refactoring or deploying changes.

high MutationObserver leak — each EV calculation adds a permanent observer

perfmemory File: expectedValuePanel.mjs:386

What: Every EV calculation attaches a new MutationObserver without disconnecting the previous one. N calculations = N chart re-renders on every theme toggle. Observers accumulate indefinitely.

Impact: Growing memory leak and multiplicative UI jank on theme switch.

high No social share images — missing og:image and twitter:card meta tags

seosocial File: BaseLayout.astro

What: Missing og:image and twitter:card meta tags. Links shared on KakaoTalk, Twitter, or Discord show no preview card — just a bare URL.

Impact: Zero social preview on all platforms. Links look untrustworthy.

high Fake contact info live — placeholder data shipped to users

content File: contact.astro:13-14

What: example@example.com and example#0000 are displayed as real contact information on the public contact page.

Impact: Users try to reach out and get nowhere. Looks abandoned.

high Privacy policy inaccurate — claims no data leaves the browser, but RUM is active

legalprivacy File: privacy.astro

What: The privacy policy states that no data leaves the user's browser. However, the Cloudflare RUM beacon sends usage events and error stacks to Cloudflare analytics.

Impact: Privacy policy is factually wrong. Potential trust/legal issue.

MEDIUM SEVERITY — Should Fix

medium Home page title duplicates expected-value page — both say "아이템 제작 횟수 기대값 계산기"

seocontent File: index.astro:6

What: The home page <title> is identical to the expected-value calculator page title. Search engines see duplicate titles. Users with multiple tabs open can't tell them apart.

medium CSP unsafe-inline — can be replaced with hashes for the two inline theme scripts

securitycsp File: _headers

What: The CSP uses 'unsafe-inline' for script-src. The only inline scripts are the two theme initialization blocks — both can be whitelisted with SHA-256 hashes, eliminating the need for unsafe-inline entirely.

medium Hardcoded pages.dev domain in robots.txt, _headers CSP, and astro.config — needs custom domain update

configdeploy File: Multiple

What: pages.dev is hardcoded in robots.txt, _headers CSP directives, and astro.config defaults. Every deployment to a custom domain requires changing these in 3+ places — easy to miss one.

medium No screenshot file size cap — multi-hundred-MB paste can freeze the tab

perfux File: deconstruction.astro:753

What: Screenshot paste handler has no file size limit. Pasting a large image (hundreds of MB) sends it straight to the OCR pipeline, freezing the main thread and potentially crashing the tab.

medium z-index stacking — dropdowns render under the sticky header

cssux File: deconstruction.astro:3063

What: Dropdown menus (item search suggestions, filter selects) have a lower z-index than the sticky header. Open a dropdown and scroll — the dropdown slides under the header, hiding options.

What: Navigation links use trailing slashes (/deconstruction/) but the sitemap lists URLs without them (/deconstruction). Search engines treat these as separate pages. Astro's trailing-slash config should be set explicitly and matched everywhere.
