ScrollBluePill — Second Comprehensive Audit

2026-07-29 · Four investigation angles: bug/regression hunt, UI/UX friction, state-model & lifecycle, code quality & maintainability

HIGH SEVERITY — Fix Now

high Active/toggle color system completely different between pages

Source: UI/UX #1

What: Every checkbox, toggle, filter chip, and segment button renders with a completely different visual language between the EV and deconstruction pages. EV uses solid-filled green-on-white; deconstruction uses semi-transparent overlays with dark text. The entire interactive color system is independently implemented on each page.

Impact: The two main tools look like they belong to different products. Identical controls behave differently visually.

Root cause: CSS duplicated rather than shared — each page has its own copy that has drifted.

Fix: Unify into one token system; extract shared CSS. Now.

high __lastDeconResult stale after reset, survives across navigations

Source: Bug #1, State #1.4

What: The reset handler clears deconHasActionableResults but never nulls window.__lastDeconResult. The pagehide listener saves it to sessionStorage. On back-navigation, tryRestoreDeconSession re-displays the old results as if reset never happened.

Reproduction: Run analysis → click 초기화 → navigate away → come back → old results reappear.

Fix: Set window.__lastDeconResult = null in every path that clears deconHasActionableResults. Now.

high Dialog button styling and order inconsistent between pages

Source: UI/UX #2

What: EV confirmation dialogs use identical styling for both buttons. Deconstruction uses red destructive buttons for confirm. Save-picker replace-confirm uses green. No consistent convention.

Fix: Standardize: confirm = green/primary, destructive = red, cancel = plain. Now.

high Large result payload in session save can silently overflow quota

Source: State #6.1

What: saveDeconTransferSession writes window.__lastDeconResult (up to 10,000+ strategy objects) to sessionStorage. If this exceeds the ~5-10MB quota, the entire save fails silently — including the small UI state fields. All draft state is lost.

Fix: Omit the result array from session save, or wrap it in a separate try/catch. Now.

high EV transfer auto-click races with DOM, silent no-op on slow devices

Source: Bug #2

What: A 50ms setTimeout auto-clicks .ev-start-btn on transfer load. openCalcPanel() gets called 3-4 times in the first 100ms, each replacing calcContent children. If the DOM isn't ready, ?.click() silently does nothing.

Fix: Replace setTimeout polling with a callback-based "ready" signal. Now.

MEDIUM SEVERITY — Fix Soon

medium ~3,500 lines of CSS duplicated across both .astro files

Source: Code #1C

What: ~80% of the CSS in deconstruction.astro is a direct copy of expected-value.astro. Every visual tweak must be applied twice. They are already drifting (see Finding #1).

Fix: Extract shared CSS into a global file or BaseLayout.astro is:global block.

medium 11 window.__ev* globals create fragile coupling

Source: Code #6A

What: The EV calculator is wired entirely through window.__ev* global functions. This makes the code impossible to unit test in Node and creates hidden bidirectional coupling between modules.

Fix: Pass callback objects at init time instead of relying on globals.

medium Item search is copy-pasted (200+ lines HTML, 200+ lines JS) across pages

Source: Code #1A

What: The entire item search system — HTML form, JS event handlers, suggestion rendering, manual filter logic — is duplicated verbatim. Any bugfix or feature addition must be applied identically in two places.

Fix: Extract into a shared module or component. Already partially done with itemSearchUI.mjs — finish the extraction.

medium mode field lost on deconstruction-to-EV transfer

Source: State #5.1

What: serializeDeconStrategy omits the mode field (manual/probability) for gems, stimulant, and item-level-up. On the EV side, all modes default to 'manual'. Probability-mode selections are silently converted.

Fix: Include mode in the serialized strategy and round-trip it.

medium No v1-to-v2 storage migration path

Source: State #8.1

What: Every storage reader checks payload.v !== 1 and silently deletes/rejects mismatched versions. If any storage schema changes to v2, all existing user data (saved slots, sessions, pending transfers) is immediately lost.

Fix: Add a migration function or use additive field changes without version bumps.

medium scrollPosition saved to sessionStorage but never restored

Source: State #2.1

What: saveDeconTransferSession saves scrollPosition: window.scrollY on every pagehide. tryRestoreDeconSession never reads or applies it. Wasted storage and code.

Fix: Either restore scroll position or remove the field.

medium .decon-confirm-overlay dead CSS from pre-<dialog> migration

Source: Bug #3

What: CSS rule for a leftover overlay class exists but no JS creates elements with that class anymore. Dead code.

Fix: Remove the CSS rule.

medium Warning/error banners lack dark mode overrides

Source: UI/UX #5

What: .manual-item-overflow-warning and .maker-stimulant-error use hardcoded light-mode colors (yellow and red backgrounds) with no dark mode adaptation.

Fix: Add :root[data-theme='dark'] overrides.

medium Stale label flashes on EV slot load/transfer restore

Source: Bug #4

What: __evSetState calls __evRefresh({ showStale: false }) after 100ms, but restoreEvState already called __evRefresh({ showStale: true }). Brief 100ms flash of "stale data" label on every restore.

Fix: Call __evRefresh with correct showStale parameter from the start.

medium No safety timeout on stuck loading states

Source: UI/UX #9

What: If the "계산 중..." / "분석 중..." loading state gets stuck (e.g., computation hangs), there's no timeout to restore the button. User must reload.

Fix: Add a 30-second setTimeout fallback that re-enables the button.

LOW SEVERITY — Polish

low Empty slot bar has no instructional label

Source: UI/UX #10

New users don't know what the dashed boxes are. Add a "저장 슬롯" label or tooltip.

low Slot bar shows no loading state during initial data fetch

Source: UI/UX #8

Empty dashed boxes appear instantly with no loading feedback. Hide until data loads or show a pulse animation.

low EV left-stack missing overflow-x: hidden

Source: UI/UX #6

Deconstruction has it; EV doesn't. Content can overflow horizontally on narrow screens.

low EV dialog uses px font-size instead of rem

Source: UI/UX #7

font-size: 14px in .ev-confirm-dialog p doesn't scale with browser font preferences. Deconstruction correctly uses 0.88rem.

low Initial page paint flickers before spinner CSS

Source: UI/UX #16

Placeholder text appears, then spinner class is added via JS. Render the loading class in the initial HTML.

low Corrupt localStorage transfer payload never cleaned up

Source: Bug #7

If a transfer payload fails JSON.parse, it stays in localStorage forever until the next transfer overwrites it.

low EV page uses .ev-start-btn class selector instead of data attribute

Source: Code #2A

Replace document.querySelector('.ev-start-btn') with [data-ev-start-btn] for resilience.

low Dual stimulant range systems confusing to users

Source: State #3.1

Editor bounds and post-hoc filter ranges look identical but serve different purposes. Add UI labels to distinguish them.

low Slot bar no responsive breakpoint for 320px screens

Source: UI/UX #15

48px slots may overflow on very narrow viewports. Allow wrapping or reduce slot size.

low Selected item card uses hardcoded #4d4c78 background

Source: UI/UX #3

No dark mode override for the item preview card background. Use a CSS variable.

Top 5 Highest-Impact Fixes

  1. Clear __lastDeconResult on reset (Finding #2) — one-line fix, prevents reset being silently undone
  2. Unify active/toggle color system (Finding #1) — most visible UX improvement
  3. Omit result array from session save (Finding #4) — prevents quota overflow wiping all draft state
  4. Fix EV transfer auto-click race (Finding #5) — transfer silently fails on slow devices
  5. Standardize dialog button conventions (Finding #3) — consistency across all confirmation flows
