ScrollBluePill — Third Comprehensive Audit

2026-08-02 · Six investigation angles: bug/correctness, UI/UX friction, state-model & lifecycle, code quality & maintainability, performance, accessibility · 4 parallel deep-read agents + manual review, ~76 source files

HIGH SEVERITY — Fix Now

high EV page returns "성공 확률: 0%" for all threshold-mode strategies

bug Source: Bug #1, Code #1

What: runEvCalculation in expected-value.astro:1451 sets probability = 0; // DP engine removed whenever canUseExactOutcome(userStrategy) is false. This triggers on item level-up in probability mode, random gems (blackAmethyst/darkCrystal), or chaos scrolls without explicit per-stat deltas — all normal usage paths. The result UI shows "성공 확률: 0%" with zero explanation.

Reproduction: EV page → select item → apply chaos scroll → 계산 시작 → "성공 확률: 0%".

Fix: Either re-add the DP/threshold engine, or detect !canUseExactOutcome(...) up front and show "이 조합은 아직 계산을 지원하지 않습니다" instead of a fake 0%.

high Deconstruction result restoration is dead code — back-navigation loses analysis

state Source: State #1, State #1H2

What: saveDeconTransferSession writes the heavy result to a separate RESULT_KEY in sessionStorage. loadDeconResult/clearDeconResult are exported but never imported or called anywhere. tryRestoreDeconSession checks saved.result — but the draft payload never includes a result field. The entire "restore results on back-navigation" feature is unreachable. Users lose their analysis on browser Back.

Fix: Call loadDeconResult() inside tryRestoreDeconSession and pass its return value as saved.result. Clean up RESULT_KEY after restore.

high __lastDeconResult never cleared — stale results survive reset and corrupt session saves

state Source: State #2, State #1H2

What: window.__lastDeconResult is set on every successful runAnalysis but never cleared — not in clearDeconCalculationState, not in the reset handler, not in guardDeconMutation. The pagehide handler saves it to RESULT_KEY unconditionally. Analyze item A → change to B → navigate away → B's draft saved with A's stale result.

Fix: Null window.__lastDeconResult in every path that clears deconHasActionableResults: reset, item change, and clear-calculation.

high Empty scroll-rate filter converted to null, silently enables ALL scrolls

bug Source: Bug #2, Engine

What: deconstruction.astro:1624 converts an empty rate-filter Set to null: deconScrollRateFilter.size > 0 ? deconScrollRateFilter : null. The engine treats null as "no filter" and uses every scroll, including chaos. filterScrollsByRate already handles empty sets correctly (return []).

Reproduction: Uncheck all 4 rate chips (100/60/10/chaos) → 분석 시작 → results appear using scrolls the user explicitly deselected.

Fix: Pass the Set through unconditionally.

high itemLevelUpPanel.deactivate() throws TypeError — selecting 0-slot item crashes the EV panel

bug Source: Bug #3, Code #1

What: deactivate() at itemLevelUpPanel.mjs:369 nulls enhancementState, then line 386 reads enhancementState.itemLevelUpSlotCount → guaranteed TypeError. Called when selecting an item with upgradeSlots <= 0 on the EV page. The error kills the handler; the reset-button-hide path never completes. Leftover from the slot-count 4→5 centering fix.

Fix: Read enhancementState.itemLevelUpSlotCount before nulling it, or delete lines 384–387 (the centering toggle is already done in renderSlots()).

high No focus indicators on all dual-range sliders — keyboard users get zero visible focus

a11y Source: UI/UX #1

What: deconstruction.astro:4391 and :4011 and expected-value.astro:1681 all set outline: none on input[type='range'] with no :focus-visible replacement. Keyboard users tabbing to any range slider (level range, stimulant bounds, chaos stats, scroll-count) get zero visible indication of focus.

Fix: input[type='range']:focus-visible { outline: 2px solid var(--green); outline-offset: 4px; }

high Result filter chips clipped and unreachable on mobile ≤480px

ux Source: UI/UX #2

What: .decon-filter-chips uses display: inline-flex with overflow: hidden, chips are white-space: nowrap. All 6–7 chips total ~465px; at ≤480px viewport the rightmost chips (색상 등급) are cut off with no way to scroll or reach them. The grade filter is completely inaccessible on phones.

Fix: flex-wrap: wrap or overflow-x: auto.

high Up to 10,000 strategy cards built into DOM then pagination hides all but 5

perf Source: Perf #1, Code #2

What: deconstruction.astro:1743 renders all strategies via result.strategies.forEach(...) with no slicing. MAX_DISPLAY_STRATEGIES = 10000. Each card contains icon <img> elements and scroll tables. All 10k subtrees are constructed, then pagination hides 9,995 of them. Initial render delay and memory pressure are unnecessary.

Fix: Render only the first page (5 cards) on initial display; build the rest lazily or paginate before DOM construction.

high Unthrottled O(10k) DOM mutation on every slider tick

perf Source: Perf #2, Code #3

What: resultFilterController.applyFilters() runs on every input event of every dual-range slider (~60/s while dragging). Each tick: iterates ALL model entries × 5 sources, querySelectorAlls all 10k cards, un-hides pagination-hidden cards (card.hidden = !visible), then pagination.applyPagination(true) re-hides them — another full 10k mutation pass. ~20k hidden-attribute toggles + 3 full DOM scans per drag tick.

Fix: Throttle to change events or rAF, and make the filter pass pagination-aware so it doesn't touch pagination-hidden cards.

MEDIUM SEVERITY — Fix Soon

medium Engine DFS prunes valid scroll + negative-stimulant strategies

bug Source: Bug #4, Engine M1

What: engine.mjs:312–319 caps maxUses for a scroll based on floor(remaining / delta) when delta > 0, forbidding any scroll whose per-stat delta exceeds the remaining target. But canReachTarget explicitly models overshoot absorbed by negative corrections from stimulant bounds (min −5). E.g. target STR +5, +10 scroll, stimulant −5: floor(5/10) = 0 → scroll skipped → the valid 1×scroll + stim(−5) strategy is never generated.

Fix: Remove the maxUses cap and rely on canReachTarget for pruning, or only cap when correctionBounds cannot go negative for the key.

medium Chaos/level-up HP/MP ignore ×10 granularity — impossible strategies displayed as valid

bug Source: Bug #5, Engine M3

What: HP/MP deltas are always multiples of 10 (enforced in the EV probability engine and UI steppers). But canChaosFillResidual only does range checking with no modulo-10 check, and enumerateRangeVectors enumerates every integer. The decon page can display strategies like "+35 maxHp from chaos" or a level-up total of 25 from 2×(10..20) — impossible in the actual game. These transfer to EV and compute 0% probability.

Fix: Enforce value % step === 0 (step 10 for HP/MP) in canChaosFillResidual and in the level-up total-range enumeration.

medium EV computation errors swallowed and shown as "성공 확률: 0%"

bug Source: Bug #6, State M5

What: The entire EV computation body is inside a single try/catch whose catch only does debug(...); probability = 0;. Any shape mismatch in a restored/saved enhancement state (old save missing itemLevelUpSlots or scrollState) yields "성공 확률: 0%" with no error surfaced. No user-visible error path exists.

Fix: Catch separately and show an explicit error message via the existing placeholder machinery. Also call trackError.

medium Transfer dedup recorded before payload applied — failed transfers lost forever

state Source: State #3, State M1

What: consumeDeconTransfer writes APPLIED_KEY (sessionStorage) before the caller applies the payload. If itemById.get(transferPayload.itemId) is missing or buildEnhancementStateFromStrategy throws, the payload is dropped but marked as applied. A refresh in the same tab deduplicates it and never retries.

Fix: Record APPLIED_KEY only after successful application — move the dedup write to after __evSetState succeeds.

medium restoreEnhancementState trusts localStorage with no validation — malformed saves crash the panel

state Source: State #4, State M2

What: Enhancement state from localStorage (user-editable, possibly from older app version) is assigned wholesale without revalidation. renderSlotRow dereferences enhancementState.scrollState.slotCount with no guard; runEvCalculation calls itemLevelUpSlots.some(...) — both throw if the shape is wrong. No clamping of saved slotCount against the item's current upgradeSlots.

Fix: Normalize the stored state: coerce arrays, clamp slotCount to the item's upgradeSlots, early-return on malformed shape.

medium Undefined CSS variables --panel and --text silently invalidate rules

css Source: UI/UX #3

What: deconstruction.astro:4353 uses var(--panel) — never defined anywhere → .decon-secondary-stimulant-row has no background. deconstruction.astro:3871 uses var(--text) — never defined → silently inherits by accident.

Fix: Replace --panel with var(--surface-soft) and --text with var(--ink).

medium --header-offset: 70px but mobile header is ~106px — scroll targets land under the header

ux Source: UI/UX #4

What: At ≤760px the header stacks brand + actions + nav wrapping (~106px), but --header-offset stays at 70px. EV page anchor jumps and deconstruction scrollIntoView targets land partially under the header on mobile.

Fix: Increase --header-offset inside the @media (max-width: 760px) block.

medium No prefers-reduced-motion anywhere — animations run for all users

medium Hardcoded brand blue ~40× and 4 different danger reds — no CSS variable consistency

medium statLabelByKey ×3, grade thresholds ×3, stepper-row builder ×4 — massive duplication

What: statLabelByKey is byte-identical in 3 files. Grade thresholds (5/22/39/56/73) copied in 3 files.
