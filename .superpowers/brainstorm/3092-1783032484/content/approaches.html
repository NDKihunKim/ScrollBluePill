Approaches for Inline Chaos Slider Rows

All achieve the same result: label + range values + slider on one row. Difference is in how we get there.

A

Flatten the JS row structure (recommended)

In resultFilterController.mjs, remove the header wrapper span. Instead of appending header + dualRange as two children, append the label + value spans + dualRange slider directly as siblings in one flex row.

JS change: Drop the header span creation. Append label, minVal, sep, maxVal, dualRange directly to rowS. The label text combines stat name + range: "공격력 -5~5".

CSS change: None needed — the existing display:flex; align-items:center; gap:4px on .decon-secondary-scroll-chaos-stat-row does the inline layout automatically.

Pros

  • Cleanest — removes the problematic header wrapper entirely
  • No CSS override needed
  • The header class (.decon-secondary-scroll-slider-header) is no longer shared between regular and chaos cards, reducing coupling

Cons

  • Slightly more JS change (5-6 lines)
B

Override CSS width for chaos rows

Keep the existing JS structure (header + dualRange). Add a CSS override so .decon-secondary-scroll-slider-header inside chaos stat rows doesn't take full width.

CSS change: Add :global(.decon-secondary-scroll-chaos-stat-row .decon-secondary-scroll-slider-header) { width: auto; flex: 0 0 auto; }

JS change: Only update the label text to include range values.

Pros

  • Minimal JS change — only the label text

Cons

  • CSS override is fragile — the header class serves two masters (regular scroll cards want full width, chaos cards want auto width)
  • Shared class coupling persists — future changes to one card type might break the other
